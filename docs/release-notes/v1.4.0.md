# Jasper v1.4.0

1.4.0 is a feature release. Features marked *Experimental* are opt-in and may change in 1.4.x patch releases as they're polished. Only the latest minor release line gets fixes.

## New (Experimental)

### SQLite database

Run Jasper without PostgreSQL by enabling the `sqlite` profile. The database is stored at `$JASPER_STORAGE/db.sqlite` (default `/var/lib/jasper`). Bulk metadata regeneration falls back to the background backfill on SQLite.

### Cloud storage (Google Cloud Storage and S3)

Store backups, cache and other files in GCS or S3 / S3-compatible buckets (MinIO, Cloudflare R2) so several pods can share storage. Enable `storage` plus `gcs` and/or `s3`. Configure `storage`, `storageBucket` and `storageRoutes` in the `_config/server` template, or with the `JASPER_OVERRIDE_SERVER_STORAGE*` environment variables. Routes can be per tenant and namespace. See the [README storage details and examples](../../README.md#profiles).

### CDN for cached video

Storage routes with a `cdnBaseUrl` serve cached HLS (M3U8) segments straight from the CDN instead of the proxy.

## Changes

- Backup and restore now **skip deleted items (tombstones) by default**. Turn on the new `tombstones` backup option to include them.
- A backup only appears once it has been fully written. A failed backup no longer leaves a partial zip behind.
- Published dates on internal Refs are now corrected automatically against their first two sources instead of being left inconsistent.

## Fixes

- The cache existence check no longer misses normal cached files.
- Origin lookup for replication no longer matches Refs from other origins.

## Upgrading from 1.3

- No manual steps for PostgreSQL. A database migration adds a small `instr()` SQL function.
- If you rely on deleted items being included in backups, set `tombstones: true` in your backup options.
- The SCIM integration no longer depends on a third-party SDK. No configuration changes.
- Cloud storage needs credentials: GCS uses Application Default Credentials (e.g. GKE Workload Identity), and S3 uses the default AWS credential chain (e.g. EKS IRSA). Set `APPLICATION_STORAGE_S3_REGION` / `APPLICATION_STORAGE_S3_ENDPOINT` as needed, and `APPLICATION_STORAGE_TMP_DIR` for zip staging space.
